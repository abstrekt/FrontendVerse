# Content visuals — diagram + animation, every time

**Rule: no new content entry ships without both.**

1. a **draw.io diagram** — the spatial idea, generated into
   `public/diagrams/<set>/<name>.svg`
2. an **animation** — a steppable ```` ```trace ```` block, rendered by
   [`src/components/VisualTrace.jsx`](../../../src/components/VisualTrace.jsx)

A diagram shows the shape. A trace shows it running. Prose alone is the thing
this rule exists to stop.

## Where the draw.io MCP fits

The repo's diagrams are **generated** — `scripts/lib/<set>-diagrams.mjs` is the
source of truth, `.drawio` and `.svg` are build outputs and are overwritten by
the next `pnpm run build:diagrams`. So never hand-edit a `.drawio` and call it
done.

Use the draw.io MCP for the two things a script cannot do:

| Step | Use the MCP for |
| --- | --- |
| Before writing coordinates | Sketch the layout on the draw.io canvas, drag boxes until it reads, then **read the resulting geometry back and port those x/y/w/h into the `build()` function.** |
| After `build:diagrams` | Open the generated `diagrams/<set>/<name>.drawio` and look at it — catch overlaps, clipped labels and a canvas that runs past 820px before it ships. |

At the start of a visual task, list the MCP's tools (`mcp__drawio__*`) and use
the ones it actually exposes — don't guess names. If the MCP is not connected,
say so, then fall back to: write the `build()`, run the build, and read the
exported SVG.

**Never** paste MCP-authored XML straight into `diagrams/` as the deliverable.
The deliverable is the `build()` function.

## Authoring a diagram

```bash
pnpm run build:diagrams                      # every set
pnpm run build:diagrams sysdesign            # one set — prefer this
pnpm run build:diagrams browser cookie-auth  # one diagram
```

| Set | Module |
| --- | --- |
| `blind75` | `scripts/lib/blind75-diagrams.mjs` |
| `sysdesign` | `scripts/lib/sysdesign-diagrams.mjs` |
| `react` | `scripts/lib/react-diagrams.mjs` |
| `browser` | `scripts/lib/browser-diagrams.mjs` |
| `webfund` | `scripts/lib/webfund-diagrams.mjs` |

Rules, all of them already enforced or warned about by the build:

- **Canvas is `W` = 820px** from `diagrams/lib/diagram-furniture.mjs`. Wider
  scales down to unreadable text in the article column.
- **Colours come from the `C` palette** in `drawio-builder.mjs`. Anything else
  ships as a fixed value, breaks in one theme, and prints `⚠ unmapped`.
- Use the shared furniture: `title(main, sub)`, `takeaway(y, …)`, `legend(…)`.
  Every diagram ends on a one-line takeaway.
- `diagram-lint.mjs` fails a cell outside the canvas and warns on clipped
  labels and partial overlaps. A warning is a bug, not noise.
- A blueprint may be **shared** by many entries (a dozen React items point at
  `memo_reference_trap`). Reuse one before inventing a near-duplicate.
- Reference it from the markdown as `![alt](/diagrams/<set>/<name>.svg)`.
- Adding a brand-new set means registering it in `SETS` in
  `scripts/generate-diagrams.mjs`.

Mermaid is acceptable **only** for a genuinely linear flow with no spatial
content; anything with layers, scope, or two things happening at once gets a
draw.io diagram.

## Authoring the animation (trace)

A ```` ```trace ```` fence of JSON inside the entry's markdown:

```
{
  "input": "nums = [3, 2, 4], target = 6",
  "lanes": [{ "id": "nums", "label": "nums", "cells": [3, 2, 4], "indices": true }],
  "vars": ["need", "map"],
  "steps": [{
    "note": "6 − 3 = 3. Not seen yet, so remember 3.",
    "cursors": { "nums": { "i": 0 } },
    "marks":   { "nums": { "0": "active" } },
    "vars":    { "need": "3", "map": "{ 3: 0 }" }
  }],
  "result": "return [1, 2]"
}
```

- Lane kinds: `cells` (default), `tree`, `slots`, `phases`, `log` — documented
  at the top of `VisualTrace.jsx`.
- Tones: `active · hit · bad · skip · window · done`. `marks` keys are an index
  (`"2"`) or an inclusive range (`"0-2"`).
- `note`, `input` and `result` render `` `code` `` and `**bold**` only.
- `scripts/lib/trace-validate.mjs` is the contract: a step may not touch a
  lane, node, slot, phase or var the trace never declared.
- **A trace must match the solution the entry publishes.** If the code changes,
  the trace changes.
- Aim for ~10 lines and 4–8 steps. Small input, one idea.

### Generated vs inline

| Section | How |
| --- | --- |
| Blind 75 | Generated. Add an entry to `scripts/lib/blind75-traces.mjs`, run `pnpm run build:traces`. |
| React (4 files) | Generated. Add `{ diagram, alt, after, trace }` to `scripts/lib/react-traces.mjs`, run `pnpm run build:react-traces`. **Coverage is enforced** — `--check` fails on any item with no entry. |
| System Design, Browser, Web Fundamentals, JS Learnings, Coding, MCQ | **Inline** in the entry's `answer` / `explanation`. No applier. |

Both appliers are idempotent and guarded in `pnpm test`:

```bash
node scripts/apply-blind75-traces.mjs --check
node scripts/apply-react-traces.mjs --check
node scripts/apply-react-traces.mjs --section=react-guide   # while authoring
```

## Per-section checklist for a new entry

1. Load [`load-quiz-content`](../../../.cursor/skills/load-quiz-content/SKILL.md)
   first — schema, ids, dedupe, curriculum module.
2. Decide the diagram: reuse an existing blueprint, or add a `build()` to the
   set's module. Sketch geometry through the draw.io MCP before typing
   coordinates.
3. `pnpm run build:diagrams <set>` and open the result through the MCP. Fix any
   lint warning or `⚠ unmapped` colour.
4. Reference the SVG from the markdown.
5. Write the trace — generated table or inline fence, per the table above.
6. `pnpm run build:data-manifest` then `pnpm test`.
7. `pnpm dev` and look at the entry: the SVG follows the theme toggle, the
   trace steps to its result.
8. Do not commit unless asked.

## The two exemptions

- An index or landing entry with no single mechanism — the React set lists
  these in `DIAGRAM_ONLY` (`react-guide` 1 and 39). Add to that list rather
  than inventing a trace that traces nothing.
- A Coding challenge whose runnable tests already *are* the animation still
  gets a diagram; the trace is optional there and only if the solution has a
  non-obvious intermediate state.

Anything else without a diagram and a trace is unfinished.
